# xDSL BLIS INT8 AXPY Implementation Report & Handoff Guide

> **Status (2026-07-17):** Design complete. Codebase audited. Four critical gaps identified and resolved below.
> This document is the canonical handoff artifact for implementing `AXPY_INT8_Pack` support.
> A subsequent LLM implementation agent should read this document top-to-bottom and apply every change listed in Section 6.

---

## 1. Overview and Motivation

The current pure xDSL BLIS pipeline effectively generates and dispatches `AXPY_FP32_Pack` and `DOT_INT8_LANE_Pack` kernels. The goal is to implement an **AXPY (Outer Product)** style kernel for **int8 × int8 → int32** (denoted as `AXPY_INT8_Pack`).

This is highly symmetric to the existing `AXPY_FP32_Pack` method but requires:
- Handling 1-byte data sizes during packing
- Emitting 8-bit-specific RVV instructions in the packing builders
- Correctly routing the `i8i8i32` microkernel from the project generator
- Fixing a critical ABI mismatch in how `alpha`/`beta` types are declared

---

## 2. Microkernel Strategy (`build_gemm_i8i8i32`)

The `build_gemm_i8i8i32` microkernel in `tests/test_codeGeneration.py` (line 270) already exists and is complete. It matches the **AXPY outer product** paradigm:

- **Matrix A**: Loaded contiguously as columns using fractional LMUL `vle8_i8mf4` and widened to `i16` via `vsext_vf2_i16mf2`.
- **Matrix B**: Loaded as a scalar (one element from the B row), sign-extended to `i16`.
- **Computation**: The accumulator is updated via vector-scalar widening multiply-add (`vwmacc_vx_i32m1`), computing `C += A_vec * B_scalar`.

### 2.1 Reference Mixed Precision Kernel — Deep Analysis

The file `tests/api_gen_cpp/merged/kernels_RVV_8x8_i8i8i32.c` is the **ground-truth reference** produced by the earlier mixed-precision xDSL pipeline. Every pure-xDSL kernel generated by `build_gemm_i8i8i32` must produce C code that is semantically identical to what is shown here. The sections below dissect the 8x8 b0 and b1 variants in full detail.

#### Function Signature and Argument Mapping

Both `b0` and `b1` variants share the same ABI:

```c
void gemm_RVV_MxN_bX_col_i8i8i32(
    void*    ctxt,   // v0  — context pointer (ignored)
    int      kc,     // v1  — depth of the micro-panel (k loop bound)
    float*   alpha,  // v2  — alpha pointer  <- float*, NOT int32_t*
    int8_t*  Ac,     // v3  — packed A panel (column-major, int8, stride=lda)
    int      lda,    // v4  — leading dim of Ac = MR (e.g. 8)
    int8_t*  Bc,     // v5  — packed B panel (row-major, int8, stride=ldb)
    int      ldb,    // v6  — leading dim of Bc = NR (e.g. 8)
    float*   beta,   // v7  — beta pointer   <- float*, NOT int32_t*
    int32_t* C,      // v8  — output tile C (column-major, int32)
    int      ldc     // v9  — leading dim of C in int32 elements
);
```

> **Key insight**: `alpha` (`v2`) and `beta` (`v7`) are `float*` even though all data is integer. This is the BLIS standard API convention. The kernel ignores them in practice (alpha=1, beta=0/1 is baked in by selecting the b0 or b1 variant). This is **exactly why `c_type_alpha = "float"` is mandatory** in the generator — it must match this ABI or you get an undefined-behavior type mismatch.

#### Constant Preamble (SSA Artifact)

Every kernel opens with a block of `size_t` constants. This is xDSL's SSA lowering materializing compile-time index values as named variables:

```c
size_t v10 = 0;   // base index / loop start
size_t v11 = 1;   // loop step; also B col offset +1
size_t v12 = 2;   // B col offset +2
size_t v13 = 3;
size_t v14 = 4;
size_t v15 = 5;
size_t v16 = 6;
size_t v17 = 7;   // B col offset +7
size_t v18 = 8;   // MR = VL = 8  (passed to every vle8/vse32 intrinsic)
int16_t v19 = 0;  // unused SSA artifact
int32_t v20 = 0;  // zero initializer for vmv_v_x (b0 only)
```

`v18 = 8` is the vector length (VL) constant used in every RVV load/store/MAC. It equals MR.
`v11`–`v17` are column offsets into `Bc`: `Bc[k*ldb + n]` uses `v43 + vN` where `vN = n`.

#### Accumulator Initialization — `b0` Mode (`C = A*B`, beta=0)

```c
// Zero-initialize NR=8 accumulators, one vint32m1_t per output column:
vint32m1_t v21 = __riscv_vmv_v_x_i32m1(v20, v18);  // acc[col=0] = {0,0,0,0,0,0,0,0}
vint32m1_t v22 = __riscv_vmv_v_x_i32m1(v20, v18);  // acc[col=1]
vint32m1_t v23 = __riscv_vmv_v_x_i32m1(v20, v18);  // acc[col=2]
vint32m1_t v24 = __riscv_vmv_v_x_i32m1(v20, v18);  // acc[col=3]
vint32m1_t v25 = __riscv_vmv_v_x_i32m1(v20, v18);  // acc[col=4]
vint32m1_t v26 = __riscv_vmv_v_x_i32m1(v20, v18);  // acc[col=5]
vint32m1_t v27 = __riscv_vmv_v_x_i32m1(v20, v18);  // acc[col=6]
vint32m1_t v28 = __riscv_vmv_v_x_i32m1(v20, v18);  // acc[col=7]
// Copied to mutable SSA names for use inside the k-loop:
vint32m1_t v29 = v21;  vint32m1_t v30 = v22;  // ...  vint32m1_t v36 = v28;
```

**xDSL builder counterpart** (`test_codeGeneration.py`):
```python
c0_i32 = arith.Constant(IntegerAttr(0, i32_t))
vl_mr  = eb.const_index(MR)
acc_init = lb.vmv_v_x_i32m1(c0_i32.result, vl_mr)
```

#### Accumulator Initialization — `b1` Mode (`C = A*B + C`, beta=1)

Instead of zeroing, the NR=8 existing C columns are **pre-loaded** from memory before the loop:

```c
// col=0: C[0*ldc .. 0*ldc+MR-1]
size_t v21 = v10 * v9;          // 0 * ldc = 0
size_t v22 = v10 + v21;         // 0
int32_t* v23 = &v8[v22];        // &C[0]
vint32m1_t v24 = __riscv_vle32_v_i32m1(v23, v18);  // load 8 x int32

// col=1: C[1*ldc .. 1*ldc+MR-1]
size_t v25 = v11 * v9;          // 1 * ldc
size_t v26 = v10 + v25;         // ldc
int32_t* v27 = &v8[v26];        // &C[ldc]
vint32m1_t v28 = __riscv_vle32_v_i32m1(v27, v18);  // load 8 x int32

// col=2..7: same pattern with n * ldc for n=2..7
// ...
// Loaded vectors copied to mutable SSA names v53..v60 for the loop.
```

**This is the ONLY structural difference between b0 and b1.** The inner k-loop body and the store epilogue are byte-for-byte identical between variants.

**xDSL builder counterpart**:
```python
# b1 mode: pre-load existing C tile
n_ldc = lb.muli(eb.const_index(n), ldc)
acc_init = lb.vle32_i32m1(C, n_ldc, vl_mr)
```

#### Inner Loop Body — Step-by-Step (identical in b0 and b1)

```c
for (size_t k = 0; k < kc; k += 1) {

    // ── STEP 1: Compute address Ac[k * lda] and load MR=8 int8 elements ──
    size_t a_off  = k * lda;             // lda = MR = 8 for packed A (col-major)
    int8_t* a_ptr = &Ac[a_off];          // pointer into packed A panel
    vint8mf4_t A_i8 = __riscv_vle8_v_i8mf4(a_ptr, 8);
    //         ^^^^^^ LMUL=MF4: fractional quarter-register
    //                holds exactly 8 int8 elements at VLEN=256

    // ── STEP 2: Widen A from int8 → int16 ONCE, reused across ALL NR MACs ──
    vint16mf2_t A_i16 = __riscv_vsext_vf2_i16mf2(A_i8, 8);
    //          ^^^^^^^ LMUL=MF2: half-register, 8 int16 elements
    //          Sign-extension required because vwmacc_vx expects i16 multiplier

    // ── STEP 3: Compute base B offset Bc[k * ldb] ────────────────────────
    size_t b_base = k * ldb;             // ldb = NR = 8 for packed B (row-major)
    // Per-column B scalar offsets are compile-time constants added to b_base:
    //   col 0: b_base + 0 = b_base
    //   col 1: b_base + 1   (= b_base + v11)
    //   col 2: b_base + 2   (= b_base + v12)
    //   ...
    //   col 7: b_base + 7   (= b_base + v17)

    // ── STEP 4: For each of the NR=8 columns — scalar load B, MAC ─────────
    //
    //   Pattern (unrolled NR times, no inner loop):
    //   - Load int8 scalar from Bc
    //   - Cast to int16
    //   - vwmacc_vx_i32m1(acc_col, b_i16_scalar, A_i16_vector, VL=8)
    //
    // col 0:
    int8_t  b0 = Bc[b_base + 0];
    int16_t b0_16 = (int16_t) b0;
    acc[0] = __riscv_vwmacc_vx_i32m1(acc[0], b0_16, A_i16, 8);
    //                                │       │       │      └─ VL=MR=8
    //                                │       │       └─ A vector (i16mf2)
    //                                │       └─ B scalar (i16, sign-extended)
    //                                └─ accumulator input AND output (i32m1)

    // col 1:
    int8_t  b1 = Bc[b_base + 1];
    int16_t b1_16 = (int16_t) b1;
    acc[1] = __riscv_vwmacc_vx_i32m1(acc[1], b1_16, A_i16, 8);

    // cols 2..7: identical pattern ...
}
```

**Key observations:**
- `vle8_v_i8mf4` always loads exactly **MR elements** regardless of NR — the vector A load count is always 1 per k-step.
- `vsext_vf2_i16mf2` is called **once per k-step**, amortized across all NR column MACs.
- `vwmacc_vx_i32m1` is the **vector-times-scalar** form: B is a scalar, A is a vector. This is the defining characteristic of the AXPY (outer product) algorithm.
- LMUL chain: `i8mf4` → widen → `i16mf2` → MAC → `i32m1`. Each step doubles element width while preserving 1 physical register, so the total register pressure is constant regardless of MR.

**xDSL builder counterpart** (`test_codeGeneration.py` lines 355–388):
```python
# Step 1 — load A column
a_offset = lb.muli(k, lda)               # k * lda
A_i8_vec = lb.vle8_i8mf4(A, a_offset, vl)

# Step 2 — widen A once
A_i16_vec = lb.vsext_vf2_i16mf2(A_i8_vec, vl)

# Step 3 — B scalar per column (inside n-loop, unrolled by Python range(nr))
b_base = lb.muli(k, ldb)
b_off  = lb.addi(b_base, eb.const_index(n))  # n = 0..NR-1
b_i8   = memref.LoadOp.get(B, [b_off])
b_i16  = arith.ExtSIOp(b_i8.res, i16_t)

# Step 4 — MAC
acc[(n, m)] = lb.vwmacc_vx_i32m1(acc[(n, m)], b_i16.result, A_i16_vec, vl)
```

#### Store Epilogue — Column-by-Column (identical in b0 and b1)

After the k-loop, each of the NR=8 accumulator registers is stored to its column of C:

```c
// col=0: store MR=8 int32 elements to C[0 .. MR-1]
int32_t* p0 = &C[0];            // offset = 0
__riscv_vse32_v_i32m1(p0, acc[0], 8);

// col=1: store to C[1*ldc .. 1*ldc+MR-1]
int32_t* p1 = &C[ldc];          // offset = 1 * ldc  (ldc = v9)
__riscv_vse32_v_i32m1(p1, acc[1], 8);

// col=2: offset = 2 * ldc
size_t off2 = 2 * ldc;
int32_t* p2 = &C[off2];
__riscv_vse32_v_i32m1(p2, acc[2], 8);

// cols 3..7: offset = n * ldc for n=3..7
```

Column-major indexing: `C[m, n] = C_ptr[n * ldc + m]`. The `vse32.v` writes elements `C[0..MR-1, n]` in one vector instruction per column.

**xDSL builder counterpart** (`test_codeGeneration.py` lines 397–415):
```python
for n in range(nr):
    c_offset = lb.muli(eb.const_index(n), ldc) if n > 0 else eb.const_index(0)
    lb.vse32_i32m1(C, c_offset, c_final[(n, m)], vl)
```

#### Register and Memory Layout Summary

| Symbol | Value (8x8) | Description |
|--------|-------------|-------------|
| VL     | 8           | Elements per RVV op = MR |
| `lda`  | MR = 8      | Packed A: stride in bytes between k-steps |
| `ldb`  | NR = 8      | Packed B: stride in bytes between k-steps |
| `ldc`  | runtime     | Output C: stride in int32 elements between columns |
| LMUL(A load) | MF4  | `vint8mf4_t` — 8 int8s at VLEN=256, quarter physical reg |
| LMUL(A wide) | MF2  | `vint16mf2_t` — 8 int16s, half physical reg |
| LMUL(C acc)  | M1   | `vint32m1_t` — 8 int32s, one full physical reg |
| Acc count    | NR = 8 | One `vint32m1_t` per output column |

#### Scaling Law: How MR x NR Changes the Kernel

| MR x NR | Acc regs | `vle8_i8mf4` per k | B scalar loads per k | `vwmacc_vx` per k | `vse32` stores |
|---------|----------|---------------------|----------------------|-------------------|----------------|
| 1x1     | 1        | 1                   | 1                    | 1                 | 1              |
| 1x4     | 4        | 1                   | 4                    | 4                 | 4              |
| 8x4     | 4        | 1                   | 4                    | 4                 | 4              |
| 8x8     | 8        | 1                   | 8                    | 8                 | 8              |

**The A vector load count is always exactly 1 per k-step, regardless of NR.** Each additional NR column costs only 1 scalar B load + 1 `vwmacc`. This is the AXPY outer-product property, and why AXPY has higher arithmetic density than DOT for large NR tiles.

### Alpha / Beta ABI (Critical)

The microkernel declares `alpha` and `beta` as **`float*`** (i.e., `MemRefType(Float32Type(), [-1])`):

```python
# test_codeGeneration.py lines 298-307
memref_f32 = MemRefType(Float32Type(), [-1])
input_types = [
    idx_t,      # kc
    memref_f32, # alpha  <- float pointer, NOT int32_t*
    memref_i8,  # A
    idx_t,      # lda
    memref_i8,  # B
    idx_t,      # ldb
    memref_f32, # beta   <- float pointer, NOT int32_t*
    memref_i32, # C
    idx_t,      # ldc
]
```

This is intentional: the BLIS driver passes `float*` for alpha/beta to match the standard BLIS API. Any integer scaling is handled inside the kernel. **The generator must declare `c_type_alpha = "float"` even for INT8 datatypes.**

### LMUL Note

`build_gemm_i8i8i32` uses `LMUL=MF4` (`vle8_i8mf4`). With `vlen=256`, each MF4 register holds `256 / (8 x 4) = 8` INT8 elements — the same count as a FP32 M1 register at VLEN=256. Therefore `vlen_elements = config.vlen // 32 = 8` is **accidentally correct** for MF4 INT8, even though the formula is written for FP32. This is safe for all currently planned MR values (<= 32 for VLEN=256). No code change is needed here, but the coincidence should not be relied upon if LMUL is ever changed.

## 3. Packing Layout for AXPY_INT8_Pack

The primary gap in the framework is the packing logic (`pack_builder.py`), which currently has no `AXPY_INT8_Pack` branch and would silently fall back to 32-bit FP32 instructions if called.

### Design Principles

- **LMUL=M1** for all packing instructions (`vle8.v`, `vlse8.v`, `vse8.v`) — maximizes bandwidth, avoids register pressure.
- **Dense 1-byte packing (no internal padding)** — the microkernel uses unit-stride loads from `Ac` and scalar loads from `Bc`, so no 4-byte alignment is needed internally.
- Global buffer allocations in the C++ driver remain 64-byte aligned.

### Packing Matrix A — `pack_RB_v_if` for INT8

Reads column-major `A` and stores contiguously to `Ac`.

**Loop structure (mirrors `build_pack_RB_v_if` for FP32 but with int8 ops):**
```
outer loop: i = 0 .. mc  step MR
  rr = min(mc - i, MR)
  inner loop: j = 0 .. kc  step 1
    src_off = j * ldM + i
    vl = SetvlE8M1(rr)              <- SetvlE8M1Op, NOT SetvlOp
    vec = vle8.v(M[src_off], vl)    <- vle8_v_i8m1Op
    dst_off = i * kc + j * MR
    vse8.v(Mc[dst_off], vec, vl)    <- vse8_v_i8m1Op
```

**Multi-vector handling for large MR:** When `MR > 32` (one full M1 register at VLEN=256), the outer body must loop over `num_vecs = ceil(MR / vlen)` chunks, exactly mirroring the FP32 AXPY pattern with `get_safe_chunk_avl`. See the FP32 reference in `build_pack_RB_v_if` (lines 126-161) — replace `vle32_v_f32m1Op` -> `vle8_v_i8m1Op` and `SetvlOp` -> `SetvlE8M1Op`.

### Packing Matrix B — `pack_CB_v_if` for INT8

Reads column-major `B` across strides, packing into `Bc` row-major.

**Loop structure (mirrors `build_pack_CB_v_if` for FP32 but with int8 ops):**
```
outer loop: j = 0 .. nc  step NR
  nr = min(nc - j, NR)
  bstr = ldM * 1               <- elem_bytes = 1 for INT8
  inner loop: i = 0 .. kc  step 1
    src_off = j * ldM + i
    vl = SetvlE8M1(nr)
    vec = vlse8.v(M[src_off], stride=bstr, vl)   <- vlse8_v_i8m1Op
    dst_off = j * kc + i * NR
    vse8.v(Mc[dst_off], vec, vl)                 <- vse8_v_i8m1Op
```

### `_else` Variants

The `_else` variants (`pack_CB_v_else`, `pack_RB_v_else`) are stub functions that immediately return. The `_if` variant already handles tail cases via the `SetvlE8M1` masking. This is consistent with the existing `DOT_INT8_LANE_Pack` pattern (lines 318-326 in `pack_builder.py`).

### Gap 1 — `c_type_alpha = "int32_t"` Causes ABI Mismatch (CRITICAL)

**File:** `tests/pure_xdsl_blis_rvv/generate_pure_blis_project.py`, lines 173-179

**Problem:**
```python
elif config.datatype in ["int8", "i8i8i32"]:
    elem_bytes = 1
    mlir_type = IntegerType(8)
    c_type_a = c_type_b = "int8_t"
    c_type_c = "int32_t"
    c_type_alpha = "int32_t"   # <-- WRONG
```

The generator emits `int32_t* alpha` and `int32_t* beta` in the forward declarations in `gemm_headers.h` and in the `gemm_dispatch_xdsl.cpp` dispatch function. However, `build_gemm_i8i8i32` lowers to C code with `float* alpha` and `float* beta`. This creates a **type mismatch between the caller (dispatcher) and the callee (generated kernel)**, which is undefined behavior in C and will silently corrupt computation or crash at runtime.

As confirmed by the reference kernel (Section 2.1): `float* v2` and `float* v7` are always float pointers in the emitted C.

**Fix:** Change line 179 to:
```python
    c_type_alpha = "float"
```

### Gap 2 — `AXPY_INT8_Pack` Missing from `pack_builder.py` (CRITICAL)

**File:** `tests/gemm_blis_xdsl/pack_builder.py`, lines 436-456

**Problem:** The `build_pack_module` dispatcher has branches for `DOT_INT8_LANE_Pack` and `DOT_FP32_LANE_Pack`, then falls through to a default branch that calls `build_pack_CB_v_if` / `build_pack_RB_v_if`. **Those functions unconditionally use FP32 RVV operations** (`vle32_v_f32m1Op`, `vlse32_v_f32m1Op`, `vse32_v_f32m1Op`) regardless of `elem_bytes`. Calling them for an INT8 buffer generates 32-bit loads on byte-aligned data, which reads 4x the intended memory.

```python
    build_pack_RB_v_if(...),   # <- always emits vle32/vse32
    build_pack_RB_v_else(...), # <- always emits vlse32/vse32
])
```

**Fix:** Add four new builder functions (see Section 6.1) and a new dispatch branch:

```python
if method == "AXPY_INT8_Pack":
```

### Gap 3 — `build_gemm` Precision Dispatch Fails for `"int8"` (CRITICAL)

**File:** `tests/test_codeGeneration.py`, line 550

**Problem:**
```python
def build_gemm(..., precision="fp32", method="AXPY_FP32_Pack"):
    if precision == "i8i8i32":          # <- only matches "i8i8i32"
        return build_gemm_i8i8i32(...)
    if method == "DOT_FP32_LANE_Pack":
        return build_gemm_dot_fp32(...)

```

The generator calls `build_gemm(..., precision=config.datatype, ...)` where `config.datatype = "int8"`. Since `"int8" != "i8i8i32"`, the dispatcher falls through and generates an **FP32 kernel for an INT8 buffer**. No error is raised.

**Fix option A (minimal, recommended):** Widen the condition in `test_codeGeneration.py`:
```python
if precision in ("i8i8i32", "int8"):
    return build_gemm_i8i8i32(...)
```

**Fix option B (also required):** Normalize the precision string in the generator before calling `build_gemm`, and fix the `default_name` to use the normalized string so the rename maps work:

```python
# In generate_pure_blis_project.py, inside the microkernel pool loop:
_precision = "i8i8i32" if config.datatype in ("int8", "i8i8i32") else config.datatype
mic_mod_b0 = build_gemm(mr=m_idx, nr=n_idx, vlen=vlen_elements,
                         beta=BetaMode.B0, precision=_precision, method=config.method)
default_name_b0 = f"xdsl_api_gemm_RVV_{m_idx}x{n_idx}_b0_col_{_precision}"
```

Without this, the rename map `{default_name_b0: new_name_b0}` would use `"int8"` for `default_name_b0` but the kernel's actual emitted name contains `"i8i8i32"` — the map would never match and the function would not be renamed.

**Both Fix A and Fix B should be applied** to be robust.

### Gap 4 — `vlen_elements` Semantics Wrong for INT8 (Latent Bug)

**File:** `tests/pure_xdsl_blis_rvv/generate_pure_blis_project.py`, line 226

**Problem:**
```python
vlen_elements = config.vlen // 32   # Assumes 32-bit element width -- always
```

For FP32 with `vlen=256`, this gives `8`, meaning 8 FP32 elements per M1 vector register.

For INT8 (`i8mf4`), this also gives `8` — but for a different reason. The MF4 register holds `vlen / (8 x 4) = 8` INT8 elements. The formula `config.vlen // 32` is mathematically equal to `config.vlen // (8 * 4)` by coincidence. This is correct **today** for LMUL=MF4, VLEN=256.

**Risk:** If the microkernel is ever changed to LMUL=M1 for INT8 (which holds 32 INT8 elements per register at VLEN=256), this would silently produce wrong tiling.

**No code change required now.** Add a comment documenting this coincidence:
```python
# NOTE: For INT8 i8mf4, capacity per fractional register = vlen/(8*4) = vlen/32
# which equals the FP32 M1 capacity. This formula is accidentally correct for MF4.
# If LMUL is changed to M1 for INT8, use: vlen_elements = config.vlen // 8
vlen_elements = config.vlen // 32
```

```python
def build_pack_CB_v_if_int8(idx: IndexType, memref_type, RR: int, elem_bytes: int,
                              suffix: str, vlen: int = 32, method: str = "AXPY_INT8_Pack"):
    """
    Pack Matrix B (CB = Column-Major B -> packed Bc row-major) for INT8 AXPY.
    Uses vle8/vlse8/vse8 with LMUL=M1. Mirrors build_pack_CB_v_if but for 8-bit.

    Arguments passed at runtime: (M, Mc, kc, nc, ldM)
    Loop: outer over j (nc, step NR), inner over i (kc, step 1).
    Load: vlse8 with stride = ldM * 1 (gathers NR elements across rows at same k).
    Store: vse8 contiguous to Bc.
    """
    fn, (M, Mc, kc, nc, ldM) = _make_fn(f"pack_CB_v_if_{method}_{suffix}_RR{RR}", memref_type, idx)
    entry = fn.body.blocks[0]
    c0, c1, cEB, cRR = _const(0, idx), _const(1, idx), _const(elem_bytes, idx), _const(RR, idx)
    entry.add_ops([c0, c1, cEB, cRR])

    ob = Block(arg_types=[idx])
    entry.add_op(scf.ForOp(c0.result, nc, cRR.result, [], Region([ob])))
    j = ob.args[0]
    rem = arith.SubiOp(nc, j)
    nr = arith.MinSIOp(rem.result, cRR.result)
    bstr = arith.MuliOp(ldM, cEB.result)
    ob.add_ops([rem, nr, bstr])

    ib = Block(arg_types=[idx])
    ob.add_op(scf.ForOp(c0.result, kc, c1.result, [], Region([ib])))
    i = ib.args[0]

    j_ldM = arith.MuliOp(j, ldM)
    src_off_base = arith.AddiOp(j_ldM.result, i)
    j_kc, i_RR = arith.MuliOp(j, kc), arith.MuliOp(i, cRR.result)
    dst_off_base = arith.AddiOp(j_kc.result, i_RR.result)
    ib.add_ops([j_ldM, src_off_base, j_kc, i_RR, dst_off_base])

    # Inline chunk loop using SetvlE8M1Op (do NOT use get_safe_chunk_avl which calls FP32 SetvlOp)
    num_vecs = (RR + vlen - 1) // vlen
    for v in range(num_vecs):
        c_chunk     = _const(v * vlen, idx)
        c_chunk_end = _const((v + 1) * vlen, idx)
        end         = arith.MinSIOp(nr.result, c_chunk_end.result)
        end_safe    = arith.MaxSIOp(end.result, c_chunk.result)
        chunk_avl   = arith.SubiOp(end_safe.result, c_chunk.result)
        vl_op       = SetvlE8M1Op(chunk_avl.result)   # <- INT8 M1 setvl
        ib.add_ops([c_chunk, c_chunk_end, end, end_safe, chunk_avl, vl_op])

        chunk_ldM     = arith.MuliOp(c_chunk.result, ldM)
        src_off_chunk = arith.AddiOp(src_off_base.result, chunk_ldM.result)
        load_op       = vlse8_v_i8m1Op(M, src_off_chunk.result, bstr.result, vl_op.vl)
        dst_off_chunk = arith.AddiOp(dst_off_base.result, c_chunk.result)
        store         = vse8_v_i8m1Op(Mc, dst_off_chunk.result, load_op.result, vl_op.vl)
        ib.add_ops([chunk_ldM, src_off_chunk, load_op, dst_off_chunk, store])

    ib.add_op(scf.YieldOp())
    ob.add_op(scf.YieldOp())
    entry.add_op(func.ReturnOp())
    return fn
```
