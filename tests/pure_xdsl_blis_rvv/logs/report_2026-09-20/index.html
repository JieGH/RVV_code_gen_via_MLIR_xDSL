Overnight GEMM runs, layer by layer

Sixteen runs of the generated xDSL BLIS kernels, 8 on jbpi and 8 on jbpi2, alternating every 30 min, first started 23:00 on 19 Sep 2026 and last started 06:30 on 20 Sep. Each run took about 7 min. Uninstrumented build, reference protocol (tmin 10 s, no warm-up), pinned to core 0. Every figure is GOPs for the whole GEMM call, packing included, the same region the reference design times. Both boards are averaged into one series, Latest work. The Layer by layer view also shows the same work modified to pack with the scalar packer instead of the vector one, Modified latest work with scalar packing (violet square), made in the afternoon and evening of 20 Sep on both boards, and the reference design alone (its own packers and kernels, nothing of ours) run the same way, 16 runs overnight from 22:58 on 20 Sep (cyan cross).

How far latest work is from a reference, per layer

Jitter, two kinds

Inside a run is how much single reps differ from each other (standard deviation ÷ mean, in percent). Between runs is how far the sixteen run means are apart ((highest − lowest) ÷ mean). S3 has only 2 reps per run and S4, S5 have 1, so they have no inside-a-run figure at all, only the between-runs one.

Where the reference numbers come from
  • Past publication ref design. The table you gave, approximate GFLOPS per layer. I have not seen the run behind it, so board, build and timing region are unknown to me.
  • Reference sweep. The reference design alone (issue 29): its own scalar packers, its Exo kernels (LDX set, macc variant) and its blocking, 16 runs, 8 on each board, every 30 min from 22:58 on 20 Sep, core 0, tmin 10 s, packing included. It ships no 32x7 or 16x15 kernel, so the value shown for S1 to S5, B4, B2 and B3 is its nearer even-NR neighbour (32x6, 16x14), not the true kernel; B1 and B5 use their exact 32x6. The other neighbour (32x8, 16x16) runs at about half the speed and is in the tooltip and the table below the chart. Made at night like the vector-pack runs, but not at the same time as them.
  • Fresh reference run. The reference design built and run on jbpi2 on 18 Sep (32x6, macc kernel, tmin 3 s, packing included). Only B1 and B5 were run, so only those two layers have a value.
  • Archived xDSL sweep. ext/*_comparison.txt. These are best-of-sweep numbers from our own older xDSL driver, not from the reference design, even though they carry the same 32x7 and 16x15 labels.
  • OpenBLAS (archived). The OpenBLAS column of the same ext files. I did not check where those were measured.
  • The sources disagree with each other (for B1: published 8.0, reference sweep 7.26, fresh single run 7.02, archived 7.38), so the chart never merges them.
  • Not included: the five jbpi2 runs from 18 Sep. They used the older warm-up protocol, and mixing protocols would blur the comparison.
