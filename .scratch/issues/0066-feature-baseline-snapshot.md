## 1. Problem

The reorganization moves about 120 files. Nothing today proves a move changed no behaviour:

- No host test generates a project for each feature. f16f16f32 and int8 projects are never generated on the host (§2 of the parent).
- `--dry-run` plans of the runners are tested one script at a time, against hand-written expectations, not against what ran before.

## 2. What to build

1. **Snapshot script** `.scratch/reports/issue-128/snapshot.sh <out-dir>`, run before any move and after each sub-issue. It writes:
   - `generated.sha256`: for every config in the folder (found by name, wherever it lives), generate the project (`generate_pure_blis_project.py --config <path>`) and hash every file under `pj_gen/`. Keyed by config basename, so a moved config compares with its old self.
   - `dryrun/<config>.txt`: `compile_macro_bench.sh --dry-run --config <path>` for every config, config paths cut to the basename. (Changed from the spec: the other runners' `--dry-run` plans are already checked by their own `test_run_*.py`, which run in the pytest part, so the snapshot does not repeat them.)
   - `pytest.txt`: the sorted list of passed test IDs, with the folder part of each file path dropped.
   - A compare mode: `snapshot.sh --compare <before> <after>` prints every difference and exits non-zero on any.
2. **Feature smoke tests** `test_features.py`: one host test per feature row of the parent's §2 that has a generator path: generate a project from a small config and check the expected files exist (kernel `.c`, packers, driver, Makefile): fp32 AXPY one tile, fp32 AXPY three-tile family, f16f16f32, int8 if the generator still supports it (if not, record it as a finding, do not fix it here).

## 3. Out of scope

- **Baseline host suite**, unmoved tree, `.venv/bin/python -m pytest` from `tests/pure_xdsl_blis_rvv`: **674 passed**, 0 failed, 16 min. (With the conda Python, 4 files fail to import `xdsl`: use `.venv`.) IDs in `baseline/pytest.txt`.
- **Baseline snapshot** `baseline/`: 45 configs, all generate; two snapshots of the same tree compare clean; one changed hash makes `--compare` exit 1.
- **Feature smoke tests** `tests/test_features.py`, 7 passed: fp32 AXPY, fp32 DOT, f16f16f32 and int8 each generate a full project; pinned rows give one project per tile in order; a pinned row with a tile list keeps only its first tile; a 7-value row (no iterations) is search mode and builds one project with every tile up to the largest.
- **Finding, not a bug:** a row's 8th value (iterations) is also what makes it pinned (`config.py:54`). Adding `iterations` to a search row silently turns it into a one-tile pinned row. Now pinned down by `test_pinned_row_with_a_family_uses_its_first_tile`.
