\section*{Glossary}
\begin{description}\setlength\itemsep{0pt}\small
\item[V, S, H] the three setups. V: our GEMM with the vector (RVV) packer. S: our GEMM with the scalar packer (\texttt{--scalar-pack}). H: H\'ector's GEMMLib \texttt{gemm.bin}, his code unchanged.
\item[1T, 8T] 1 thread, 8 threads (OpenMP).
\item[core 4, cores 0--7] the cores used. 1T never runs on core 0 (it takes every device interrupt); 8T needs all 8 cores, so it includes core 0 (the user's 8-thread exception).
\item[thread binding] \texttt{OMP\_PROC\_BIND=close OMP\_PLACES=cores}: each OpenMP thread stays on one core. Used for all three setups at 8T.
\item[tile MRxNR] the microkernel's block of C, MR rows by NR columns. Ours: 24x8 on every shape. H\'ector's: 16x8, and 16x4 when n = 4.
\item[shape] one YOLO26 layer as an m x n x k GEMM; 50 shapes (\texttt{datasets/yolo26\_k1.dat}, no n = 1 rows).
\item[launch] one run of one setup over all 50 shapes at one thread count. Written ``launch 1/2/3''.
\item[round] one block of 1T launches and one block of 8T launches, one launch per setup each; 3 rounds.
\item[A-B-B-A order] the order of thread counts over the rounds, 1T 8T, 8T 1T, 1T 8T; inside a block the setup order rotates (V S H, S H V, H V S), so each setup takes each place once.
\item[reference protocol] the timing loop of the reference design and of H\'ector's driver: no warm-up, call the GEMM until \texttt{tmin} seconds have passed, divide by the number of calls; the result is checked after timing.
\item[\texttt{--tmin}, \texttt{TIMIN}] that time budget per shape: 2 s on both sides.
\item[uninstrumented build] \texttt{INSTRUMENTED=0}: no timers inside the GEMM. The only build used for these numbers.
\item[GOPs by mean time] 2mnk / mean time per call. The only metric H\'ector's driver gives.
\item[one pass] each of the 50 shapes once. Pass time = sum over the shapes of the time per call (averaged over the 3 launches); pass GOPs = total operations / pass time.
\item[launch range] lowest and highest pass GOPs of the single launches.
\item[speedup] 1T pass time / 8T pass time.
\item[scalar oracle, PASS] a plain triple-loop GEMM in the driver; PASS = our C within a relative error of max(1e-5, k$\cdot$1e-6) of it.
\end{description}

\section{Setup}
\begin{itemize}\setlength\itemsep{1pt}
\item Same as \iss{56}: tile 24x8, the 50 YOLO26 shapes, board jbpi, uninstrumented build, reference protocol, \texttt{--tmin 2}, \texttt{--no-nc-overrides}.
\item New: S added, and V, S and H mixed in one series (\iss{56} compared with H\'ector's \iss{62} runs from 8 hours earlier).
\item Same run settings on both sides (user, 18 Nov): time budget, cores and 8T thread binding. H\'ector's \iss{62} runs had no binding; here his 8T launches get the same \texttt{OMP\_PROC\_BIND}/\texttt{OMP\_PLACES} as ours (environment only, his code unchanged). The compilers still differ: ours g++ 13.2 \texttt{-O2}, his gcc-14 \texttt{-O3}.
\item Driver \texttt{run\_issue94.sh}; series \input{\D/series.tex}.
\end{itemize}
